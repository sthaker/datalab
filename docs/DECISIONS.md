# Decision log

Choices made on 9 and 10 November 2026, with the reason for each. Add new entries at the bottom with a date. Do not rewrite old entries; add a new one that supersedes.

Basis of each reason: **G** stated in the private parent guide, **C** evident in the code, commit history or the earlier `CLAUDE.md`, **I** inferred by the author of this log from the code and the constraints (the owner made the choice; the written reason was not recorded). Confirm an **I** entry with the owner before reversing it.

| # | Date | Decision | Reason | Basis | Revisit when |
|---|---|---|---|---|---|
| 1 | 9 Nov | **One file.** The whole app is `index.html`, vanilla JS, no build step, no dependencies. | It must run as a GitHub Pages file and, unchanged, as a Claude artifact. One file means "both copies identical" is a byte comparison. Any future session can read all of it. No toolchain to break for a single maintainer. | C | The file passes roughly 3,000 lines, or content needs non-developers to edit it. First step then is to split content into a second file, not to add a framework. |
| 2 | 9 Nov | **Python later, not R.** Phase 2 of `k7` uses Python although the IDS curriculum uses R. | A parent can review Python. The best free short lessons (Kaggle Learn) are in Python. The IDS R package could not be confirmed to still install. | G | Never, unless the kid chooses R. |
| 3 | 9 Nov | **CODAP** as the data tool for `k7` Phase 1 and `k4` Phase 3. | Free, runs in a browser with no account, built for this age, drag-and-drop graphs, ships with example data (Mammals). The Bootstrap Data Literacy sequence has a CODAP edition to draw on. | G | CODAP links or menus change (steps were written from memory of the tool), or it proves unusable without a mouse. |
| 4 | 9 Nov | **GitHub, not Google Drive, for sync.** Progress lives as JSON files in a private repo, written through the contents API. | The owner chose it. A static page can call the contents API with a pasted fine-grained token scoped to one repo: no OAuth client, no sign-in screen, no backend. Kids need no account. Every save is a commit, so history and backup are free. Drive would need an OAuth client and a parent's Google sign-in on each kid device, which exposes far more than one folder. | Choice: owner. Reasons: I | Token expiry becomes a recurring chore, or write volume hits API limits. |
| 5 | 9 Nov | **Names out of the public page.** `KIDS` holds only "Seventh grader" and "Fourth grader". Names are typed in Parent view and stored in the parent doc. | The repo and page are public. Children's names, school and location must not be. | C | Never. |
| 6 | 9 Nov | **Paper-first mission cards** for `k4`, with "I did it from my card". | Starting on a screen is a barrier for the younger kid. The sessions are about real objects; the screen is only needed for the check. | G, C | The kid prefers the screen. Keep both paths. |
| 7 | 9 Nov | **Weekly streak, not daily.** Weeks on target is the main streak; days in a row is a bonus that never shows as broken. | The plan is three sessions a week. The reviewer pointed out a daily streak punishes the plan. Days in a row was kept because the owner asked for stickiness. | G | The weekly goal changes. |
| 8 | 9 Nov | **Gates at 9 of 10 with unseen items**, unlimited retakes, a signed product on the second unit. | 90% mastery before moving on. The reviewer showed that a gate built only from lesson questions proves little, and that a retake limit could lock a kid out. | G | A gate is passed by retaking until the draw is lucky. Then enlarge the `extra` pool. |
| 9 | 9 Nov | **Coach and AI grading only in the hosted copy.** The public page has no AI. | The public page cannot call a model without exposing a key. A kid's device should not be signed in to a parent's Claude account. A skeptical parent asked for no AI tutor in the trial. | G, C | The trial succeeds and the parents choose to turn it on for a supervised computer. |
| 10 | 9 Nov | **Lexend for body text, not a font with a slashed zero.** | The content is full of numbers read by a 9-year-old. A slashed or dotted zero looks like a different symbol to a child who has only seen a plain 0 at school. Lexend is drawn for reading ease and has a plain zero. | I | A kid misreads digits. |
| 11 | 9 Nov | **Narrower figures on phones.** `FW()` lays figures out at 340 px under a 560 px window, 520 px otherwise, instead of scaling one wide drawing down. | A 520 px drawing scaled down to a phone made axis labels too small to read. Laying out near the real width keeps figure text close to 12 px. Found on a 390 px phone on the first day and confirmed by the phone audit. | C | Tablets in portrait look sparse; add a middle width. |
| 12 | 10 Nov | **Tryout mode, not a third "test" kid.** "Grown-ups: try the lessons" runs any session or gate in practice mode and writes nothing. | A third kid would need its own synced doc, would show up on Home as a person, and would need erasing. The earlier advice (do real sessions, then Erase) put a parent's test answers into a kid's record and the progress repo. Tryout is provably inert: a test asserts storage is byte-identical before and after. No parent code, so a skeptical adult can look without setup. | Decision: owner. Reasons: I | Parents want to see their own tryout history. |
| 13 | 10 Nov | **Unfinished-session notes stay on the device.** `datalab:wip:<kid>` is never synced. | Where a kid stopped is transient. Syncing it would add a remote write (a commit) per step, a new merge rule, and conflicts between devices, for little value: a kid almost always resumes on the same device. Device-only keeps `Store.merge` unchanged. | Decision: owner. Reasons: I | Kids routinely stop on one device and resume on another. |

## Smaller choices worth knowing

| Choice | Reason | Basis |
|---|---|---|
| Parent code is a speed bump stored in plain text | It keeps a kid out of the sign-off and erase buttons. Real security would need accounts, which the constraints rule out. The page says so. | C |
| Erase works by bumping an `epoch` | With merge-on-sync, deleting data on one device would be undone by the next device. A higher epoch wins whole. | C |
| A public progress repo is refused at Connect | Names and progress would be exposed. | C |
| Test-outs do not count as sessions | The week-4 decision counts sessions done; skipping must not inflate it. | G |
| No per-session payment, points or leaderboard | Judged to teach working for the payout; a leaderboard between the two kids invites comparison across ages. | G |
| `k7` logs three numbers a day, not five | The reviewer flagged that the analysis session could stall on an unfinished log. Reaction times are the fallback. | G |
| Later units are written just before a kid reaches them | So the next unit can use that kid's real results and interests. | G |
| `noindex, nofollow` on the page | It is a family tool, not a product. | C |
